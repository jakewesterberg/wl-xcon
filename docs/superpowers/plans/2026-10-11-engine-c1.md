**Goal:** A task file defines one task object: its trial structures by name and the default one its runs play, what each of its settings means and whether it is a criterion or a stimulus, what it offers to choose (or that it offers nothing), how its reaction time is defined and whether it needs a fixed head; every consumer takes it, the load-time check refuses one that leaves any of that undeclared, and each run records the task by a hash of its content.

**Architecture:** `wl_xcon/task.py` gains the declarations (`Meaning`, with its kind, role and the reference its direction reads from; `ReactionTime`; `Choice` and `NO_CHOICE`) and the `Task` that holds them beside its `Trial` structures; `Task.params` is the union of its structures' settings, which `Session.set` validates against. A new `wl_xcon/declarations.py` holds what is declared once for every task: the shared list of the common settings' meanings (`COMMON`), the table of the bounded settings' meanings (`BOUNDED`, outside `bounds.py`), each setting's meaning as resolved (`resolved`), and the task's content hash (`content_hash`, under `FORMAT`). `check.check_task` runs `check` on each structure and adds the task-level findings. `cli._load_task` replaces `_load_trial`, and the rig (`taskd`, `preflight`, `service`), `wlx run`, `wlx check`, `wlx review` (`review.render_task`) and the simulator take the task object. Runs still play one block of the default structure until build C2.

**Tech Stack:** Python 3.11-3.13; dataclasses; `hashlib` and `json` from the standard library; pytest. **No new dependency.**

**Spec:** `docs/superpowers/specs/2026-10-07-engine-design.md` (approved 2026-10-07) §3.5, §13.3, §18.1, §20.1, §21, §22, §24's C row; `docs/superpowers/specs/2026-10-10-xc288-training-records-design.md` (approved 2026-10-10) §4.1, §4.3, §4.4, and §4.2 only as far as leaving room for stages (build C7); `docs/references/decisions.md` TRN-03 and STE-25. ## What the PI should know

Things this plan does or does not do, in plain terms, beyond Appendix B.

1. **A task file that does not say what its settings do will not load**, nor one that does not say how its reaction time is measured, **nor one that does not say what it offers to choose**: a task offering nothing writes so (`NO_CHOICE`), so a forgotten choice cannot pass for none. A file written the old way (a trial with no task object around it) is refused with a sentence saying how to wrap it.
2. **Each setting says whether it is a criterion or a stimulus** (your decision). The two bounded settings -- what a correct trial pays and the out-of-cage limit -- are proposed as **neither**, a consequence and a session limit: that third value is yours to confirm (Appendix B, item 3).
3. **A direction reads from a reference.** A setting whose values are a list of looks has no "higher" or "lower", so its direction reads "changing it makes the task harder", a cost over the next few trials, with going back to a familiar look not harder (item 1). Otherwise a direction reads on raising the value, or on moving it away from a number (a position's distance from 0), from another setting (the training variant's red and green brightness, each from the other: the gap is a cue beside color, and narrowing it is the fading path toward isoluminance), or from the trial's background (the fixation point, which vanishes on the search tasks' gray as it nears the gray's brightness) (item 2).
4. **`eccentricity`, which three task files use, is declared by each task instead**, because it means two things: the search ring's radius (expected, harder) and, in `adaptive_detection`, nothing yet, its trial reading it nowhere, so it is declared not a difficulty setting with that note (items 19, 20). `contrast` also moves nothing yet (XC-242) and keeps its clear-cut direction with that note (item 21), so the record never teaches an agent that either has no effect. The shared list holds 15 settings.
5. **No reference task declares that it needs a fixed head**, so each still runs in a chaired session with the head-free warning, as today. The refusal is built and tested on a test task, and **fails closed**: a task that needs a fixed head is refused in every session but a head-fixed one, a cage-side session as much as a chaired one (item 31; Appendix A, item 1).
6. **The task's version in the record is a hash of what it declares**, not its file: a copy of the file under another name is the same task, a comment changes nothing, a changed starting value or meaning makes a new version, and so does a change to the shared list for every task using that setting, or to a bounded setting's meaning for every task rewarding through it. **A changed framework default moves every hash too**: the hash carries the version of the defaults it was read with, and a test lists every default and fails until that version is raised. Which wl-xcon ran a session is not recorded until build C4 (XC-340).
7. **A task can hold several trial structures, but its runs still play only the default one** until build C2 lets a condition name its structure.
8. **Some settings combine into a trial no animal can get right**: a search target that looks like its distractors, a target hold at least as long as the response window (the window also times the hold), and a set size of 2 while the target's color varies (two items have no odd one). Nothing in C1 checks combinations of settings; filed for build C3, whose varying conditions and live edits make them (XC-343).
9. **How much a setting varies within a block matters as much as its value**: uncertainty about where a target will appear makes it harder to see, and a position held fixed lets an animal skip the feature it is meant to use. C1 gives each value a meaning, not each variation; recording that a setting varied is filed for build C3 (XC-344).
10. **Some of what reads "harder" is the rig's or chance's, not the animal's**: beyond about 10° the tracker can lose the eye's fourth Purkinje image, and as a search array grows, chance falls to 1 in n. The notes say so where it applies (items 14, 15, 22 and 23).
11. **A defect found on the way, not fixed here**: two `Reward` actions compare equal whatever reward entry they name, so a test comparing two tasks' trials cannot see a different reward entry. Nothing delivers by that comparison; the content hash reads the entry itself. Filed as XC-342.

## Calls taken in this plan

Engineering decisions made without asking; each says what it costs if wrong.

1. **The task object is `Task(structures, default, reaction_time, choice, meanings, needs_fixed_head)`** in `wl_xcon/task.py`, beside the vocabulary its structures are written in. Plans (C2), procedures (D) and stages with their pass rules (C7; XC-288 §4.2) join it later as fields with defaults, so a task file written now loads unchanged then. Its shape is refused as it is built, as a `Param`'s start is (`__post_init__`); what it declares is checked at load. Cost: field names, before any task in wl-xtasks uses them.
2. **A task file defines exactly one `Task`; a file with trials and no task object is refused, saying how to wrap them**, never wrapped automatically: a wrapped bare trial would declare no meaning and no reaction time and be refused a moment later for the wrong-seeming reason. Cost: six test fixtures that write task files gain a `Task(...)` line.
3. **Every declared setting needs a meaning, live or not**: a value chosen at a run's start is a change to what the animal experiences as much as a live edit (build C5's start values). Cost: a `live=False` setting needs a declaration too.
4. **How a direction reads** (`Meaning.raising`, read relative to `Meaning.relative_to`): `None`, raising the value; a number, moving the value away from it (0 for a position, whose side is not its difficulty); the name of another setting the task declares, moving away from that setting's current value (the training variant's red and green, each from the other); `BACKGROUND`, moving a luminance away from the trial's background (the fixation point, on black and on the search tasks' gray alike); and for a list of choices (`Param.choices`), changing it, since choices have no order. The load-time check refuses a reference naming no other setting the task declares, and any reference on a list of choices (`bad-meaning`). Appendix B items 1 and 2 (the domain review, 2026-10-11, replacing the first draft's `from_zero`). Cost if the PI prefers ordered choices: `raising` reads along the order the choices are written, and the three list settings' choices are reordered easiest first.
5. **The shared list holds every setting two or more reference task files use alike: 15 names**, the nine that three or more task files use, but `eccentricity`, and seven used by two files (`target_window` and `target_position` by the two detection tasks; `item_window`, `set_size`, `target_index`, `array_phase` and `distractors` by the search task and its training variant, which is a task file of its own and would otherwise repeat each). `eccentricity` is used by three files and means two things -- the search ring's radius, and in `adaptive_detection` nothing yet -- so each declares its own (the domain review; Appendix B items 19 and 20). Cost: an entry the PI would rather each task declared moves into those tasks' `meanings`.
6. **An override is a task's own `Meaning` with `overrides` set to why**; refused without it (`override-without-why`) and refused set on a name the shared list does not have (`bad-meaning`); the hash and the review report carry it. One real override is proposed: the two search tasks' `target_looks` (Appendix B, item 28). Cost: none.
7. **The bounded settings' meanings are `declarations.BOUNDED`** (`reward_correct`, `out_of_cage`), outside `bounds.py` as XC-288 §4.1 says, each with the role `NEITHER`. The check refuses a task that rewards through an entry the table does not have; a test holds the table to every ceiling the reference bounded configs carry; the out-of-cage limit's entry is read by nothing until the change log (build C3). Cost: a new ceiling name needs a table entry.
8. **A reaction time is declared by states**: from entering one state to leaving it for one of the named places (a state or an outcome). It reads off what build C7's event log records (every state entered and left, with why, XC-288 §3.2), needs no event code, and a trial that left the state another way has none. Its note says it starts at the state's entry, the frame the stimulus is commanded, which comes before the display's onset (`After`'s docstring). Cost: a reaction time that spans states, or ends inside one (a saccade's onset before its landing), cannot be said until C7 widens it.
9. **Every task must define a reaction time**: no task without a response exists yet, so there is no way to declare none. Filed: XC-341. Cost: one marker when such a task is written.
10. **A choice is a set of windows (or an array's item families) and one act** (`CHOSEN_BY`: saccade, gaze, touch, lever), checked against the transitions that fire on them. **A task offering none says `NO_CHOICE`, and an unset choice is refused (`undeclared-choice`)**, as an unset reaction time is, since a forgotten choice cannot be told from none (XC-288 §4.1's reason; the engineering review, I2). The detection tasks and the calibration task say `NO_CHOICE`: one target is where to look, not a choice. Cost: one line in each task offering none.

## Review Focus

The five inputs most likely to bite that no task's own tests would otherwise exercise, each pinned by a test in its owning task:

1. **A task file written before C1 (a bare `Trial`, no `Task`) offered to `wlx taskd`.** Expected: refused by the loader with a sentence saying how to wrap it; the pre-flight's task-checks item fails and `wlx taskd` goes on. # --- The task object (engine spec §3.5; engine build C1) --------------------------------
```python
#
# A task file defines one `Task`: its trial structures by name, the default one its runs play until
# plans exist (engine build C2), and what XC-288 §4 has a task declare about itself: what each of
# its settings means, which of its items count as choices, and how its reaction time is defined.
# Its format is defined here, in wl-xcon (the PI, 2026-10-11; the engine C1 plan). Plans (C2),
# procedures (D) and stages (C7) join it as fields with defaults.

#: What a setting's meaning may be (XC-288 §4.1; TRN-03): clear-cut with a direction, expected
#: with a direction and a context note, or not a difficulty setting.
CLEAR_CUT = "clear-cut"
EXPECTED = "expected"
NOT_DIFFICULTY = "not a difficulty setting"
MEANING_KINDS = (CLEAR_CUT, EXPECTED, NOT_DIFFICULTY)

#: Which way a clear-cut or expected setting moves the task.
EASIER = "easier"
HARDER = "harder"
DIRECTIONS = (EASIER, HARDER)

#: What a setting is (the PI, 2026-10-11): a **criterion**, what counts as success -- a window, a
#: hold, a timeout, a response window -- or a **stimulus**, what the animal sees -- brightness,
#: size, position, look -- or **neither**: the bounded settings, a consequence and a session limit.
CRITERION = "criterion"
STIMULUS = "stimulus"
NEITHER = "neither"
ROLES = (CRITERION, STIMULUS, NEITHER)


@dataclass(frozen=True, slots=True)
class Background:
    """`Meaning.relative_to`'s "the trial's background": a direction read on moving a luminance
    away from that of the background the trial is shown on (`Trial.background`; black when that
    is `None`)."""


BACKGROUND = Background()


def _text(value: object, what: str) -> None:
    """`value` is text, or a `ValueError` naming `what`."""
    if not isinstance(value, str):
        raise ValueError(f"{what} is text, not {type(value).__name__}")


def _reference(value: object) -> bool:
    """Whether a direction can read from `value` (`Meaning.relative_to`): `None`, a finite number
    that is not a `bool`, a setting's name, or `BACKGROUND`."""
    if value is None or isinstance(value, Background):
        return True
    if isinstance(value, str):
        return bool(value)
    return (
        isinstance(value, (int, float)) and not isinstance(value, bool) and math.isfinite(value)
    )


@dataclass(frozen=True, slots=True)
class Meaning:
    """What changing one setting does to the task (XC-288 §4.1; TRN-03), so a change to it can be
    recorded as easier or harder, or as neither, and an expected direction is never recorded as a
    fact; and **whether the setting is a criterion or a stimulus** (`role`; the PI, 2026-10-11),
    so a lenient criterion is never read as an easier stimulus.

    **`raising` reads relative to `relative_to`** (the engine C1 plan's call 4): with `None`, what
    raising the value does; with a number, what moving the value away from it does (0 for a
    position, whose side is not its difficulty); with another setting's name, what moving the
    value away from that setting's current value does; with `BACKGROUND`, what moving a luminance
    away from the trial's background does. For a setting whose values are choices
    (`Param.choices`), which have no order, it is what changing it does. `overrides` is set only
    where a task overrides the shared meaning of a common setting (`declarations.COMMON`), and
    says why (the PI, 2026-10-11)."""

    kind: str
    role: str
    raising: "str | None" = None
    note: str = ""
    relative_to: "float | str | Background | None" = None
    overrides: str = ""

    def __post_init__(self) -> None:
        if self.kind not in MEANING_KINDS:
            raise ValueError(
                f"a setting's meaning is {', '.join(repr(k) for k in MEANING_KINDS)}, "
                f"not {self.kind!r}"
            )
        if self.role not in ROLES:
            raise ValueError(
                f"a setting's role is {', '.join(repr(r) for r in ROLES)}, not {self.role!r}: "
                f"what counts as success, what the animal sees, or neither (the PI, 2026-10-11)"
            )
        _text(self.note, "a meaning's note")
        _text(self.overrides, "why a meaning overrides the shared one")
        if not _reference(self.relative_to):
            raise ValueError(
                f"a meaning's relative_to is None (raising the value), a number, another "
                f"setting's name or BACKGROUND, not {self.relative_to!r}"
            )
        if self.kind == NOT_DIFFICULTY:
            if self.raising is not None or self.relative_to is not None:
                raise ValueError(
                    "a setting that is not a difficulty setting moves the task neither way, "
                    "so it takes no direction"
                )
            return
        if self.raising not in DIRECTIONS:
            raise ValueError(
                f"a setting that is {self.kind} says which way raising it moves the task, "
                f"{EASIER!r} or {HARDER!r}, not {self.raising!r}"
            )
        if self.kind == EXPECTED and not self.note.strip():
            raise ValueError(
                "an expected direction comes with a note on why it might not hold for an "
                "animal (XC-288 §4.1)"
            )


@dataclass(frozen=True, slots=True)
class ReactionTime:
    """How a task's reaction time is defined (XC-288 §4.3), so one column means one thing per task:
    from the instant a trial entered `state` to the instant it left that state for one of `to` (a
    state's name or an `Outcome`). A trial that left it any other way -- a timeout, a break -- has
    none. `note` says in words what it measures (the engine C1 plan's call 8)."""

    state: str
    to: tuple
    note: str

    def __post_init__(self) -> None:
        _text(self.state, "a reaction time's state")
        _text(self.note, "a reaction time's note")
        if not self.state or not self.note.strip():
            raise ValueError("a reaction time names its state and says what it measures")
        if not isinstance(self.to, tuple) or not self.to:
            raise ValueError(
                "a reaction time ends where its state is left for: a tuple of states or "
                "outcomes, at least one"
            )
        for end in self.to:
            if not isinstance(end, (str, Outcome)):
                raise ValueError(
                    f"a reaction time ends on leaving for a state or an outcome, not {end!r}"
                )


#: What choosing an item is (XC-288 §4.3), as the guards that make it: a saccade landing, gaze
#: entering or held, a touch, a lever.
CHOSEN_BY: "dict[str, tuple[type, ...]]" = {
    "saccade": (SaccadeTo,),
    "gaze": (Entered, Hold),
    "touch": (Touched,),
    "lever": (Pressed, Released),
}


@dataclass(frozen=True, slots=True)
class Choice:
    """What a task offers to choose between (XC-288 §4.3): the windows -- or an array's item
    families, `"search.target"` -- whose items count as choices, and what choosing one is, one of
    `CHOSEN_BY`, so each trial can record the one chosen (engine build C7)."""

    items: tuple
    by: str

    def __post_init__(self) -> None:
        if not isinstance(self.items, tuple) or not self.items:
            raise ValueError("a choice names its items: a tuple of windows, at least one")
        for item in self.items:
            if not isinstance(item, str) or not item:
                raise ValueError(f"a choice's item is a window's name, not {item!r}")
        if self.by not in CHOSEN_BY:
            raise ValueError(f"a choice is made by {', '.join(CHOSEN_BY)}, not {self.by!r}")


@dataclass(frozen=True, slots=True)
class NoChoice:
    """`Task.choice`'s "this task offers nothing to choose between" (XC-288 §4.3), which leaving
    `choice` unset cannot mean: unset is refused at load (`check.check_task`'s
    `undeclared-choice`), so a task offering none says so, as a window with nothing in it says
    `REMEMBERED`, and a forgotten choice cannot pass for no choice."""


NO_CHOICE = NoChoice()


@dataclass(frozen=True, slots=True)
class Task:
    """One task (engine spec §3.5): its trial structures by name (§13.3), `default` the one its runs
    play until plans exist (engine build C2), and what XC-288 §4 has it declare: what its settings
    mean beyond the shared list (`meanings`; `declarations.COMMON`), what it offers to choose --
    a `Choice`, or `NO_CHOICE` -- and how its reaction time is defined. **Its shape is refused as
    it is built**, as a `Param`'s start is; what it declares is checked at load
    (`check.check_task`), which refuses an unset reaction time or choice."""

    structures: "dict[str, Trial]"
    default: str
    reaction_time: "ReactionTime | None" = None
    choice: "Choice | NoChoice | None" = None
    meanings: "dict[str, Meaning]" = field(default_factory=dict)

    def __post_init__(self) -> None:
        if not isinstance(self.structures, dict) or not self.structures:
            raise ValueError("a task has its trial structures, by name: a dict, at least one")
        for name, structure in self.structures.items():
            if not isinstance(name, str) or not name:
                raise ValueError(f"a trial structure is named by text, not {name!r}")
            if not isinstance(structure, Trial):
                raise ValueError(f"structure {name!r} is a Trial, not {type(structure).__name__}")
        if self.default not in self.structures:
            raise ValueError(
                f"the task's default structure {self.default!r} is not one of its structures "
                f"({', '.join(self.structures)})"
            )
        if self.reaction_time is not None and not isinstance(self.reaction_time, ReactionTime):
            raise ValueError("a task's reaction_time is a ReactionTime")
        if self.choice is not None and not isinstance(self.choice, (Choice, NoChoice)):
            raise ValueError("a task's choice is a Choice, or NO_CHOICE when it offers none")
        if not isinstance(self.meanings, dict):
            raise ValueError("a task's meanings are a dict of setting names to Meanings")
        for name, meaning in self.meanings.items():
            if not isinstance(name, str) or not isinstance(meaning, Meaning):
                raise ValueError(
                    f"a task's meanings name a setting by text and give it a Meaning; {name!r} "
                    f"does not"
                )

    @property
    def trial(self) -> Trial:

        structure's first, each name once: what `Session.set` validates against and a run's
        values are held to. A name two structures declare differently is refused at load
        (`check_task`); here the first declaration stands."""
        union: dict[str, Param] = {}
        for name in (self.default, *(other for other in self.structures if other != self.default)):
            for param in self.structures[name].params:
                union.setdefault(param.name, param)
        return list(union.values())
```

```python
def _vocabulary() -> dict[str, type]:
    """Every class a task's content can hold, by name: each dataclass `wl_xcon.task` defines -- its
    vocabulary, the declarations and the task object -- and `wl_xcon.photometry`'s colors and
    contrasts."""
    found = {
        name: value for name, value in vars(vocabulary).items()
        if isinstance(value, type) and dataclasses.is_dataclass(value)
        and value.__module__ == vocabulary.__name__
    }
    found.update({
        name: value for name, value in vars(photometry).items()
        if isinstance(value, type) and issubclass(value, (photometry.Color, photometry.Contrast))
    })
    return found


def _defaults() -> dict[str, dict[str, object]]:
    """`DEFAULTS` as the code reads now."""
    now: dict[str, dict[str, object]] = {}
    for name, cls in sorted(_vocabulary().items()):
        now[name] = {}
        for spec in dataclasses.fields(cls):
            if spec.default is not dataclasses.MISSING:
                now[name][spec.name] = canonical(spec.default)
            elif spec.default_factory is not dataclasses.MISSING:
                now[name][spec.name] = canonical(spec.default_factory())
            else:
                now[name][spec.name] = REQUIRED
    return now


def _classes(value: object, found: set[str]) -> set[str]:
    """Every class `canonical`'s plain data names, at any depth, added to `found`."""
    if isinstance(value, dict):
        if "class" in value:
            found.add(value["class"])
        for item in value.values():
            _classes(item, found)
    elif isinstance(value, list):
        for item in value:
            _classes(item, found)
    return found
```

```python
#: **The content's format** (the engine C1 plan's call 11), part of every task's content: raised
#: when a field's default changes, since `canonical` leaves a field at its default out and the
#: change would otherwise alter what a task does without moving its hash. A field added at its
#: default needs no raise. `tests/test_declarations.py` holds every default to the format it was
#: written at (`DEFAULTS`).
FORMAT = 1


def rewarded_through(task: Task) -> set[str]:
    """The bounded-config entries `task`'s structures reward through, by name (`Reward.ref`)."""
    return {
        action.ref.name
        for structure in task.structures.values()
        for _, action in actions_of(structure)
        if isinstance(action, Reward)
    }


def _at_default(spec: dataclasses.Field, value: object) -> bool:
    """Whether a dataclass field holds the default its class declares."""
    if spec.default is not dataclasses.MISSING:
        return value == spec.default
    if spec.default_factory is not dataclasses.MISSING:
        return value == spec.default_factory()
    return False


def canonical(value: object) -> object:
    """`value` as plain data for the content hash (the engine C1 plan's call 11): each declaration
    by its class's name and the fields it sets away from their defaults -- so a field a later build
    adds, at its default, leaves every task's hash as it was, and a default that changes raises
    `FORMAT` -- an `Enum` by its class and value, and sequences and text-keyed dicts element by
    element. **A `Reward` is read for the entry it names before the dataclass rule**, which would
    read no field of it (call 19). Anything else raises `TypeError`: a value written by its
    address would make every process's hash its own."""
    if value is None or isinstance(value, (bool, int, float, str)):
        return value
    if isinstance(value, Enum):
        return {"enum": type(value).__name__, "value": canonical(value.value)}
    if isinstance(value, (list, tuple)):
        return [canonical(item) for item in value]
    if isinstance(value, dict):
        for key in value:
            if not isinstance(key, str):
                raise TypeError(f"a declaration's keys are text, and {key!r} is not")
        return {key: canonical(item) for key, item in value.items()}
    if isinstance(value, Reward):
        return {"class": "Reward", "fields": {"ref": canonical(value.ref)}}
    if isinstance(value, Unchanged):
        return {"class": "Unchanged", "fields": {}}
    if dataclasses.is_dataclass(value) and not isinstance(value, type):
        return {"class": type(value).__name__, "fields": {
            spec.name: canonical(getattr(value, spec.name))
            for spec in dataclasses.fields(value)
            if not _at_default(spec, getattr(value, spec.name))
        }}
    raise TypeError(
        f"{type(value).__name__!r} is not a declaration the task's content hash can read"
    )


def content(task: Task) -> dict:
    """What `task` declares, as `canonical` writes it (XC-288 §4.4), under the content's `FORMAT`:
    the task object -- its structures, default, reaction time, choice, own meanings and whether it
    needs a fixed head -- every setting's meaning as resolved, since a shared meaning is part of
    what a task declares, and the meaning of each bounded setting it rewards through, which its
    review report shows beside the hash. Not its file, its path, or its between-trial Python
    (call 11)."""
    return {
        "format": FORMAT,
        "task": canonical(task),
        "meanings": canonical({name: meaning for name, (meaning, _) in resolved(task).items()}),
        "bounded": canonical(
            {ref: BOUNDED[ref] for ref in rewarded_through(task) if ref in BOUNDED}
        ),
    }


def content_hash(task: Task) -> str:
    """The task's identity in the record (XC-288 §4.4: "always: a hash of its content, never its file
    path"): `"sha256:"` and the hex digest of `content(task)` written as JSON with sorted keys and
    no spaces. Each run's start row carries it as `versions.task` (`taskd.Session.run`)."""
    text = json.dumps(content(task), sort_keys=True, separators=(",", ":"), ensure_ascii=True)
    return "sha256:" + hashlib.sha256(text.encode("ascii")).hexdigest()
```

```python
def check_task(
    task: Task,
    allocation: Allocation = PROVISIONAL,
    components: Registry | None = None,
    geometry: Geometry | None = None,
    calibration: Calibration | None = None,
) -> list[Finding]:
    """The load-time checks of a task object (engine spec §3.5; engine build C1): each trial
    structure's own (`check`), named by its structure where the task has several (the engine C1
    plan's call 13), then what the task declares across them -- one set of settings and one setup,
    every setting's meaning (XC-288 §4.1), its reaction time and its choice (§4.3), and a content
    its runs can record (§4.4). **What a caller holds a task to is this**; `check` is one
    structure's part of it, and stays what a bare `Trial` is checked by."""
    several = len(task.structures) > 1
    findings: list[Finding] = []
    for name, structure in task.structures.items():
        for finding in check(structure, allocation, components, geometry, calibration):
            findings.append(
                dataclasses.replace(finding, detail=f"in structure {name!r}: {finding.detail}")
                if several else finding
            )
    return (
        findings
        + _structure_faults(task)
        + _meaning_faults(task)
        + _reaction_time_faults(task)
        + _choice_faults(task)
        + _hash_faults(task)
    )


def _structure_faults(task: Task) -> list[Finding]:
    """One set of settings and one setup across a task's structures (engine spec §3.5, §13.3): a name
    two structures declare differently would be validated by `Session.set` against whichever came
    first, and a task's runs are checked against one field."""
    findings: list[Finding] = []
    first: dict[str, tuple[str, Param]] = {}
    for name, structure in task.structures.items():
        for param in structure.params:
            where, declared = first.setdefault(param.name, (name, param))
            if declared != param:
                findings.append(Finding("parameter-mismatch", (
                    f"setting {param.name!r} is declared one way by structure {where!r} and "
                    f"another by {name!r}; a task's settings are one set, which a live edit is "
                    f"checked against (engine spec §3.5)")))
    views = sorted({str(structure.view) for structure in task.structures.values()})
    if len(views) > 1:
        findings.append(Finding("view-mismatch", (
            f"the task's structures are written for different setups ({', '.join(views)}); a "
            f"task runs in one")))
    return findings


def _meaning_faults(task: Task) -> list[Finding]:
    """Every setting a person can change declares what it means (XC-288 §4.1; TRN-03): the shared
    list's (`declarations.COMMON`), or the task's own -- which, for a setting on the shared list, is
    an override and says why (the PI, 2026-10-11). **Required**: "a missing declaration cannot be
    told from a forgotten one". The bounded settings a task rewards through take theirs from
    `declarations.BOUNDED`. A meaning for no setting, an override of nothing, a direction read
    relative to anything on a list of choices, and one read relative to no other setting the task
    declares are refused too."""
    from wl_xcon.declarations import BOUNDED, COMMON, rewarded_through

    findings: list[Finding] = []
    declared = {param.name: param for param in task.params}
    for name, param in declared.items():
        own = task.meanings.get(name)
        meaning = own if own is not None else COMMON.get(name)
        if meaning is None:
            findings.append(Finding("undeclared-meaning", (
                f"setting {name!r} declares no meaning: clear-cut with a direction, expected with "
                f"a direction and a note, or not a difficulty setting (XC-288 §4.1); a missing "
                f"declaration cannot be told from a forgotten one")))
            continue
        if own is not None and name in COMMON and not own.overrides.strip():
            findings.append(Finding("override-without-why", (
                f"the task gives {name!r} a meaning of its own, and {name!r} is on the shared "
                f"list; a task overrides a shared meaning only with a note saying why "
                f"(Meaning.overrides)")))
        if own is not None and name not in COMMON and own.overrides:
            findings.append(Finding("bad-meaning", (
                f"{name!r}'s meaning says it overrides the shared list, which has no "
                f"{name!r}")))
        relative = meaning.relative_to
        if relative is not None and param.choices:
            findings.append(Finding("bad-meaning", (
                f"{name!r}'s direction reads relative to {relative!r}, and its values are "
                f"choices, which are no distance from anything")))
        elif isinstance(relative, str) and (relative == name or relative not in declared):
            findings.append(Finding("bad-meaning", (
                f"{name!r}'s direction reads relative to setting {relative!r}, which is not "
                f"another setting the task declares")))
    for name in task.meanings:
        if name not in declared:
            findings.append(Finding("meaning-for-nothing", (
                f"the task declares a meaning for {name!r}, which none of its structures "
                f"declares as a setting")))
    for ref in sorted(rewarded_through(task)):
        if ref not in BOUNDED:
            findings.append(Finding("undeclared-meaning", (
                f"bounded setting {ref!r}, which the task rewards through, has no meaning in "
                f"declarations.BOUNDED (XC-288 §4.1)")))
    return findings


def _reaction_time_faults(task: Task) -> list[Finding]:
    """How the task's reaction time is defined (XC-288 §4.3): declared, from a state some structure
    has, ending where that state's transitions go (the engine C1 plan's call 8)."""
    timed = task.reaction_time
    if timed is None:
        return [Finding("no-reaction-time", (
            "the task does not say how its reaction time is defined, from which event to which "
            "(XC-288 §4.3), so its trials' reaction times would mean nothing; declare "
            "reaction_time=ReactionTime(state, to, note)"))]
    states = [
        state
        for structure in task.structures.values()
        for state in structure.states
        if state.name == timed.state
    ]
    if not states:
        return [Finding("bad-reaction-time", (
            f"the reaction time is timed from state {timed.state!r}, which no structure has"))]
    leaves = {edge.to for state in states for edge in state.go}
    return [
        Finding("bad-reaction-time", (
            f"the reaction time ends when {timed.state!r} is left for {_destination(end)}, and "
            f"no structure's {timed.state!r} goes there"))
        for end in timed.to
        if end not in leaves
    ]


def _destination(end: object) -> str:
    """Where a transition goes, as a finding names it: an outcome by its name, a state quoted."""
    return end.name if isinstance(end, Outcome) else repr(end)


def _choice_faults(task: Task) -> list[Finding]:
    """What the task offers to choose between (XC-288 §4.3): declared -- a `Choice`, or `NO_CHOICE`
    for a task that offers none, since an unset choice cannot be told from a forgotten one (the
    engine C1 plan's call 10) -- and each item a window some structure's transition fires on by
    the act the choice names (`CHOSEN_BY`)."""
    choice = task.choice
    if choice is None:
        return [Finding("undeclared-choice", (
            "the task does not say what it offers to choose between (XC-288 §4.3), and an unset "
            "choice cannot be told from a forgotten one; declare choice=Choice(items, by), or "
            "choice=NO_CHOICE for a task that offers none"))]
    if isinstance(choice, NoChoice):
        return []
    acts = CHOSEN_BY[choice.by]
    chosen = {
        _chosen(edge.guard)
        for structure in task.structures.values()
        for state in structure.states
        for edge in state.go
        if isinstance(edge.guard, acts)
    }
    return [
        Finding("bad-choice", (
            f"{item!r} is declared a choice made by {choice.by}, and no structure's transition "
            f"fires on a {choice.by} to it"))
        for item in choice.items
        if item not in chosen
    ]


def _chosen(guard: object) -> "str | None":
    """The window -- or, for a lever, the device -- a choosing guard names."""
    return getattr(guard, "window", None) or getattr(guard, "device", None)


def _hash_faults(task: Task) -> list[Finding]:
    """A run records which version of its task it ran by the task's content hash (XC-288 §4.4), so
    a task whose content cannot be hashed is refused before any run."""
    from wl_xcon.declarations import content_hash

    try:
        content_hash(task)
    except (TypeError, ValueError) as unread:
        return [Finding("unhashable-task", (
            f"the task's content could not be hashed ({unread}), so a run could not record which "
            f"version of it ran (XC-288 §4.4)"))]
    return []
```

```python
def _load_task(path: Path) -> Task:
    """Import a task file and return the task object it defines (engine spec §3.5; engine build
    C1): exactly one `Task`, which holds its trial structures and says what its settings mean, what
    it offers to choose and how its reaction time is defined (XC-288 §4). **A file defining trials
    and no task object -- one written before engine build C1 -- is refused, saying how to wrap
    them**, never run as a task that declares nothing about itself (the engine C1 plan's call 2).

    Tasks are plain Python declarations (ADR-0006), so loading one is an import. That is also why
    the checks run *at load*: by the time this returns, the task is a data structure that can be
    inspected rather than a program to be trusted.
    """
    spec = importlib.util.spec_from_file_location(path.stem, path)
    if spec is None or spec.loader is None:
        raise SystemExit(f"cannot load {path}")
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    found = list(vars(module).values())
    tasks = [value for value in found if isinstance(value, Task)]
    if len(tasks) != 1:
        trials = sum(isinstance(value, Trial) for value in found)
        why = (
            f": it defines {trials} trial structure(s) and no Task, and since engine build C1 a "
            f"task file wraps its trials in one Task(...) that says what its settings mean and "
            f"how its reaction time is defined (engine spec §3.5; XC-288 §4)"
            if not tasks and trials else ""
        )
        raise SystemExit(f"{path} defines {len(tasks)} task objects; expected exactly 1{why}")
    return tasks[0]
```

```python
def render_task(task: Task, allocation_names: dict[int, str] | None = None) -> str:
    """A task's review report (engine spec §18.1; engine build C1). **First what a reviewer
    confirms** (XC-288 §4: "the person reviewing the task confirms it, in the review report"): the
    task's content hash, each setting's role, meaning and where it comes from -- the shared list,
    the task's own, or the task's override of the shared list with why (the PI, 2026-10-11) -- the
    bounded settings it rewards through, how its reaction time is defined, what it offers to
    choose, and whether it needs a fixed head. **Then each trial structure**, the default first,
    as `render` draws one, a heading level down. Nothing is checked first, as `wlx review` checks
    nothing: an undeclared meaning is shown as one, and a content that cannot be hashed says so."""
    from wl_xcon.declarations import BOUNDED, OVERRIDE, content_hash, resolved, rewarded_through

    try:
        identity = "`" + content_hash(task) + "`"
    except (TypeError, ValueError) as unread:
        identity = "**cannot be hashed**: " + _cell(str(unread))
    lines = [
        "# Task review",
        "",
        f"Content: {identity} (XC-288 §4.4), as each run's start row names it.",
        "",
        "## What a reviewer confirms",
        "",
        "### What each setting means",
        "",
        "| Setting | Unit | Role | Meaning | Direction | Note | From |",
        "|---|---|---|---|---|---|---|",
    ]
    meanings = resolved(task)
    for param in task.params:
        found = meanings.get(param.name)
        if found is None:
            lines.append(f"| {param.name} | {param.unit} | **UNDECLARED** | | | | |")
            continue
        meaning, origin = found
        source = origin + ": " + _cell(meaning.overrides) if origin == OVERRIDE else origin
        lines.append(
            f"| {param.name} | {param.unit} | {meaning.role} | {meaning.kind} "
            f"| {_direction(meaning, param)} | {_cell(meaning.note)} | {source} |"
        )
    lines.append("")
    rewarded = sorted(rewarded_through(task))
    if rewarded:
        lines += ["### Bounded settings it rewards through", "",
                  "| Setting | Role | Meaning | Note |", "|---|---|---|---|"]
        for name in rewarded:
            meaning = BOUNDED.get(name)
            lines.append(
                f"| {name} | **UNDECLARED** | | |" if meaning is None
                else f"| {name} | {meaning.role} | {meaning.kind} | {_cell(meaning.note)} |"
            )
        lines.append("")
    timed = task.reaction_time
    if timed is None:
        said = "**Not declared.**"
    else:
        ends = " or ".join("`" + _target_label(end) + "`" for end in timed.to)
        said = f"From entering `{timed.state}` to leaving it for {ends}: {_cell(timed.note)}."
    lines += ["### Reaction time", "", said, ""]
    if task.choice is None:
        offered = "**Not declared.**"
    elif isinstance(task.choice, NoChoice):
        offered = "None: the task offers no choice."
    else:
        items = ", ".join("`" + item + "`" for item in task.choice.items)
        offered = f"{items}, chosen by a {task.choice.by}."
    lines += ["### Choice", "", offered, ""]
    head = (
        "Needs a fixed head: refused in any session whose head is not fixed (engine spec §20.1)."
        if task.needs_fixed_head
        else "Runs with the head fixed or free; a chaired session lists its free head as a warning."
    )
    lines += ["### Head", "", head, ""]
    for name in (task.default, *(other for other in task.structures if other != task.default)):
        heading = f"## Structure `{name}`"
        if name == task.default:
            heading += ", the default: its runs play it until plans exist (engine build C2)"
        lines += [heading, "", _demoted(render(task.structures[name], allocation_names)), ""]
    return "\n".join(lines)


def _demoted(text: str) -> str:
    """`render`'s report a heading level down, to sit under its structure's heading."""
    return "\n".join("#" + line if line.startswith("## ") else line for line in text.split("\n"))


def _cell(text: str) -> str:
    """Text for one cell of a Markdown table: a bar escaped, a line break a space."""
    return text.replace("|", "\\|").replace("\n", " ")


def _direction(meaning, param) -> str:
    """Which way a setting moves the task, as `Meaning.raising` reads (the engine C1 plan's call
    4): changing a list of choices; raising a number; or moving it away from what it reads
    relative to -- a number, another setting, or the trial's background."""
    if meaning.raising is None:
        return "none"
    if param.choices:
        return f"changing it: {meaning.raising}"
    relative = meaning.relative_to
    if relative is None:
        return f"raising it: {meaning.raising}"
    if isinstance(relative, Background):
        return f"farther from the background: {meaning.raising}"
    if isinstance(relative, str):
        return f"farther from `{relative}`: {meaning.raising}"
    return f"farther from {relative:g}: {meaning.raising}"
```

Every meaning this plan proposes, as a numbered list for your confirmation before C1 merges (your decision of 2026-10-11). Each setting says how changing it moves the task: **clear-cut** (it always does, in that direction), **expected** (it usually does, with a note on why an animal might differ), or **not a difficulty setting**. Following your instruction, "expected" wherever the direction depends on the animal or the task. The reasons cite papers in the lab's library by key. A paper named "(not in the library)" was named from memory by this plan's domain review and has not been opened here; it is filed to be added and checked (XC-345).

**Three reading rules**

1. **A setting whose values are a list of looks** (the target's look, the distractors' look) has no "higher" or "lower". Proposed: its direction reads "changing it makes the task harder (or easier)", and the note says the cost is **transient** -- over the next few trials -- and that going back to a familiar look is not harder. The alternative: list the looks from easiest to hardest, and read the direction along that order. Reason: an easiest-first order is animal- and pair-specific, and your own example ("a distinct change along a feature dimension that is orthogonal to the utility in the task can make it harder to understand") is about changing a look; priming from one trial's look fades over the next several (Maljkovic and Nakayama 1994, not in the library).
2. **A direction reads relative to a reference.** Raising a value, unless the setting says otherwise: moving it away from **a number** (0 for a position that can be left or right of center: left is not harder than right, distance is what changes difficulty); away from **another setting the task declares** (the training variant's red and green brightness, each read from the other); or away from **the trial's background** (the fixation point's brightness: on black, brighter is easier; on the search tasks' 16 cd/m² gray, a point near 16 vanishes). The load-time check refuses a reference naming no other setting the task declares.
3. **Each setting is a criterion or a stimulus** (your decision). Proposed third value, **neither**, for the two bounded settings alone: what a correct trial pays is a consequence, and the out-of-cage limit is a session limit. Reason: neither is what counts as success or what the animal sees, and an agent should not read either as one.

**The shared list** (settings two or more task files use alike; each task using one inherits it)

4. **`fix_timeout`** (time allowed to look at the fixation point) -- criterion; clear-cut: raising it makes the task easier. Reason: more time can only make a missed start less likely.
5. **`fix_hold`** (how long fixation must be held) -- criterion; clear-cut, harder. Reason: your own example of a clear-cut setting, a hold's duration.
6. **`fix_window`** (the fixation window's size) -- criterion; clear-cut, easier. Reason: your own example, a fixation window's size.
7. **`fix_luminance`** (the fixation point's brightness) -- stimulus; expected, easier **the farther it is from the background** (rule 2); note: "a point farther in luminance from the background is easier to find: on black a brighter one; on a gray one farther above or below it, so a point near the gray's luminance can vanish". Reason: on the search tasks' gray, raising it from 0 toward 16 cd/m² makes the point vanish, so "raising it" alone would be wrong there.
8. **`response_window`** (time allowed to respond after the target) -- criterion; clear-cut, easier. Reason: more time to answer can only let more answers in. In the detection tasks a wrong saccade does not end the trial, so a long window also lets an animal find the target by scanning.
9. **`target_hold`** (how long gaze must stay on the target) -- criterion; clear-cut, harder. Reason: a hold's duration. In these tasks the response window also times the hold, so a hold at least as long as the window can never be met (see "What the PI should know", item 8).
10. **`target_window`** (the target window's size) -- criterion; clear-cut, easier. Reason: a window's size; the detection tasks have no distractor window, so a wider one only helps.
11. **`item_window`** (each search item's window) -- criterion; **expected**, easier; note: "a wider window accepts a less accurate landing on the target, and can also turn a near-miss beside a distractor into a wrong target". Reason: in search a landing outside every window can still be corrected, and a wider distractor window can turn it into an error instead.
12. **`target_looks`** (a lone target's look: disc or square) -- stimulus; expected, changing it harder (rule 1); note: "where to look does not change, but a new look can slow or confuse an animal over the next few trials: a change along a feature the task does not use; going back to a familiar look is not harder". Reason: your own example of a change along a feature the task does not use.
13. **`target_luminance`** (the target's brightness on black) -- stimulus; expected, easier; note: "a brighter target is easier to see on black; saccade latency falls as intensity rises and then levels off, so far above threshold more light changes little". Reason: in monkeys saccade latency falls with intensity and then levels off (Bell and colleagues 2006, not in the library); the reference tasks' 40 cd/m² is far above threshold.
14. **`target_position`** (where the target is, ±16°) -- stimulus; expected, harder **the farther from 0** (rule 2); note: "farther from fixation a saccade lands less accurately, and beyond about 10 degrees the tracker can lose the eye's fourth Purkinje image, which is the rig's harder, not the animal's; near the center the direction can turn over, the target sitting by the fixation window and small saccades being slower; which side can matter to an animal with a bias". Reason: saccade endpoints scatter more with eccentricity [@opstal1989scatter] (human); the eye's fourth Purkinje image is visible to about 10° of gaze (EYE-03); small saccades start later (Kalesnykas and Hallett 1994, not in the library).
15. **`set_size`** (how many items in the search array) -- stimulus; expected, harder; note: "while an animal learns, more items mean fewer lucky guesses, chance being 1/n, which is chance's harder, not the animal's; once it finds the odd item, more items change little". Reason: for an odd-colored target, reaction times stayed flat as distractors were added [@bravo1992role] (human). A set size of 2 has no odd item when the target's color varies ("What the PI should know", item 8).
16. **`distractors`** (the distractors' look) -- stimulus; expected, changing it harder (rule 1); note: "read with the target's look: a change can leave the target looking like the distractors, with no answer, or differing by color, by shape or by both, which is easier; a color swap slows the next few trials (priming of pop-out)". Reason: changing the target and distractor colors between trials produces priming of pop-out [@bichot2002priming]; the listed choices allow identical items, a color-only or shape-only difference, or both, and a difference in both is found faster (Krummenacher and colleagues 2001, not in the library).
17. **`target_index`** (which ring position holds the target) -- stimulus; not a difficulty setting. Reason: its number has no order of difficulty; a position bias shows in the outcomes by where the target is on screen.
18. **`array_phase`** (the ring's rotation) -- stimulus; not a difficulty setting. Reason: it turns the whole ring. Held fixed together with item 17, it lets an animal answer by position rather than by color.

**Settings each task declares for itself**

19. **`eccentricity` in `visual_search` and `visual_search_training`** (the search ring's radius) -- stimulus; expected, harder; **not on the shared list**, though three task files use it, because it means a different thing in each task using it (item 20); note: "a wider ring makes the array sparser, which weakens pop-out; red-green sensitivity falls farther from fixation; and saccades scatter more while the item windows stay as they are". Reason: item spacing relative to eccentricity is fixed by set size alone, so a wider ring does not ease crowding; a sparser array weakens pop-out (Nothdurft 2000, not in the library); red-green sensitivity falls with eccentricity (Mullen and Kingdom 2002, not in the library); endpoint scatter grows with eccentricity [@opstal1989scatter] while the windows stay at most 1°.
20. **`eccentricity` in `adaptive_detection`** -- stimulus; **not a difficulty setting**; note: "nothing reads it yet: the target's distance is target_position's, and this setting moves nothing on screen until a between-trial procedure is called (XC-242)". Reason: no part of its trial reads it; a direction for it would teach an agent that it has no effect.
21. **`contrast`** (`adaptive_detection`) -- stimulus; clear-cut, easier; note: "nothing reads it yet: no stimulus draws with it, and nothing moves it until a between-trial procedure is called (XC-242)". Reason: detection rises with contrast, and the task's own staircase assumes it, raising contrast after an error; the note keeps the record from teaching an agent "no effect" meanwhile.
22. **`target_x`** (`calibration`) -- stimulus; expected, harder **the farther from 0** (rule 2); note: "farther from the center a target is harder to fixate accurately and an uncalibrated map's error grows; beyond about 10 degrees the tracker can lose the eye's fourth Purkinje image, which is the rig's harder, not the animal's; near the center the direction can turn over, small saccades being slower". Reason: as item 14 [@opstal1989scatter]; P4 to about 10° (EYE-03); the calibration's schedule sets these more than a trainer does.
23. **`target_y`** (`calibration`) -- as item 22.
24. **`cal_window`** (`calibration`) -- criterion; clear-cut, easier. Reason: a window's size. A wider one also admits fixations off the target into the map.
25. **`cal_hold`** (`calibration`) -- criterion; clear-cut, harder. Reason: a hold's duration.
26. **`red_luminance`** (`visual_search_training`) -- stimulus; expected, easier **the farther from `green_luminance`** (rule 2); note: "the cue it adds is the brightness gap between the red and the green, redundant with their color, so a larger gap is easier; near equal brightness, whose point for this animal is unknown, the direction is uncertain; narrowing the gap is the fading path toward isoluminance". Reason: the brightness gap is a second cue beside color, so a larger one helps; its turning point is the other color's current value (green is settable 0 to 57), not a fixed number; narrowing a redundant cue step by step is fading (Terrace 1963, not in the library).
27. **`green_luminance`** (`visual_search_training`) -- the same, **the farther from `red_luminance`**.

**The one override**

28. **`target_looks` in `visual_search` and `visual_search_training`** -- overrides item 12: stimulus; expected, changing it harder (rule 1); note: "read with the distractors: the target's look is the feature it pops out on, and a swap of its color slows the next few trials (priming of pop-out); a change can leave it looking like the distractors, with no answer, and a shape difference guides search less surely than a color one"; why it overrides: "in search the target's look is the feature that pops out, not a lone target's shape".
