# b2b-ready Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the rig's https page is safe to switch on. Nothing about it can stop `wlx serve` or the rig PC's page. A member's page never shows a sign-in it cannot use. One sign-in belongs to one tab.

**Architecture:** the server half comes first.
- **`signin`.** The checker knows why it has no keys. It answers that before looking at a token. A keys thread (`Checker.keep_keys`) loads after binding, retries, then refreshes.
- **`serve`.** It turns every https setup failure into "the https page is off, because …" and serves the rig PC's page regardless.

The page half changes only the sign-in block of `web._SCRIPT`:
- one lapse rule bounds every stuck state;
- only wl.works' own OAuth error ends a renewal;
- the rig's `expired` wins;
- a Web Lock per sign-in finds a duplicated tab;
- a page that could offer no sign-in asks again and reloads.

**Tech Stack:** Python 3.11+, pytest, stdlib `http.server` and `ssl`, PyJWT with `cryptography` (the `signin` extra), and Playwright (the `browser` extra) with Chromium, plus WebKit run by hand.

**Spec:** `docs/superpowers/specs/2026-10-06-b2b-ready-design.md`, approved by the PI 2026-10-06. It builds on `docs/superpowers/specs/2026-10-02-p4d2b-b2b-remote-signin-design.md` (the b2b spec). The b2-ready spec is the authority. Where this plan and the spec differ, the spec wins and the difference is a defect in this plan, to be reported, except where a Ruling below says otherwise and why.

## Rulings in this plan

1. **§4.3's sentence covers every confirmation the rig cannot give**, not only a renewal's: "this rig has not confirmed the sign-in; trying again". A fresh sign-in or a reload whose `/whoami` cannot reach the rig had the same stuck state, with no retry. Task 5 amends spec §4.3 to say so.
2. **§4.1's lapse, made exact.**
   - A renewal begun before the token's lapse ends with the lapse.
   - One begun at or after it gets `RETRY_MS`; this covers a tab whose timers were held back, and the rig's `expired` (§4.4).
   - A lapse at which no renewal is in flight renews once more first, unless the rig never confirmed the sign-in. This is how b2b spec §4 renews "on waking a tab whose token has lapsed". It also keeps `test_an_outage_shorter_than_the_token_leaves_the_sign_in_standing` true: its retry falls due at the lapse itself, and a lapse timer armed earlier would otherwise sign the page out first.
   - wl.works still out of reach on that last try signs the page out, as before.

   Task 5 amends spec §4.1 to say so.
3. **The page's two intervals are rendered by Python** as `data-retry-ms` and `data-recheck-ms` on `<body>`, from `web.SIGNIN_RETRY_MS` and `web.KEYS_RECHECK_MS`, so a browser test can shorten them. Their values are the spec's: 30 s and 60 s.
4. **`keep_keys` reports the first outcome and the keys' arrival.** Spec §3.2's "or back" cannot happen: a refresh never drops the keys.
5. **The off sentence's words live in `web.HTTPS_OFF`** ("the rig's https page is off"). Both the terminal and the rig PC's page use it.
6. **`_https_setup`'s sentences lose their leading "refused: "**, since they no longer refuse. They are otherwise unchanged.
7. **`Checker.retry_until_ready` is replaced by `keep_keys`** and deleted with its test (Task 2).

## Review Focus

1. **A press in the seconds after `wlx serve` restarts, before its keys thread has loaded.** That is now every restart (§3.2). The press is refused with the keys-unavailable sentence. The sign-in stays, and the next press works. Test: Task 3.
2. **A TLS key that is not a key.** Its path and contents reach neither the terminal nor the rig PC's page when the https page is off because of it. Test: Task 2 (reworked).

    """Wait for `condition`, asking every 20 ms (housekeeping); fail by name after `seconds`."""

def test_the_keys_thread_loads_at_once_retries_then_refreshes_and_says_only_the_changes(tmp_path, monkeypatch):
    """b2b-ready §3.2-§3.3: the first load as soon as it starts, again every RETRY_EVERY_S
    until the keys arrive, then the key set every KEY_REFRESH_S. The terminal hears the first
    outcome and the arrival, never a retry or a refresh that changes nothing."""
    monkeypatch.setattr(signin, "RETRY_EVERY_S", 0.05)
    monkeypatch.setattr(signin, "KEY_REFRESH_S", 0.05)
    issuer = Issuer()
    issuer.down = True
    checker = _checker(tmp_path, issuer)
    said: list[str] = []
    stop = threading.Event()
    thread = threading.Thread(target=checker.keep_keys, args=(stop, said.append), daemon=True)
    thread.start()
    try:
        _eventually(lambda: len(said) == 1)
        assert signin.NO_KEYS in said[0]
        fetched = len(issuer.fetched)
        _eventually(lambda: len(issuer.fetched) > fetched + 1)  # tried again while down
        issuer.down = False
        _eventually(lambda: checker.ready)
        _eventually(lambda: len(said) == 2)
        assert "from wl.works" in said[1]
        issuer.kid = "rotated"
        _eventually(lambda: checker.key_ids() == {"rotated"})  # a refresh, on its own
        stop.wait(0.3)  # housekeeping: several more refreshes
        assert len(said) == 2
    finally:
        stop.set()
        thread.join(5)
    assert not thread.is_alive()

```python
    def refresh(self) -> bool:
        """Fetch the key set again (b2b-ready §3.3). A set with a usable key replaces the
        held one and is cached beside the held discovery document. A failure, or a set
        with none, keeps the held keys: an outage changes nothing (spec §7). True when it
        replaced them."""
        with self._lock:
            discovery, document = self._discovery, self._document
        if discovery is None:
            return False
        try:
            jwks = self._fetch(discovery.jwks_uri)
            keys = _keys(jwks)
        except (OSError, ValueError, http.client.HTTPException):
            return False
        if not keys:
            return False
        with self._lock:
            self._keys = keys
        if document is not None:
            try:
                _save(self.cache, document, jwks)
            except OSError:
                pass  # New keys are good whether or not they can be kept.
        return True

    def keep_keys(self, stop: threading.Event, say) -> None:
        """The keys thread (b2b-ready §3.2-§3.3). It loads at once, then again every
        `RETRY_EVERY_S` until the rig holds keys, then fetches the key set every
        `KEY_REFRESH_S`, until `stop` is set. `say` gets the first load's sentence, and the
        sentence of a later load that brings the keys. A refresh never drops the keys, so
        the rig never goes back to none."""
        say(self.load())
        held = self.ready
        while not stop.wait(KEY_REFRESH_S if held else RETRY_EVERY_S):
            if held:
                self.refresh()
                continue
            said = self.load()
            if self.ready:
                say(said)
                held = True
```
